# 작업: HTML 내장 데이터를 외부 JSON 파일로 분리

CSS와 실행 JavaScript가 분리된 Vite vanilla 프로젝트입니다.

이번 작업에서는 `index.html` 안에 포함된 한자 및 독해 JSON을 외부 파일로 옮기고, 사이트가 외부 JSON을 읽도록 변경하세요.

## 가장 중요한 조건

- 이름에 `backup`이 들어간 파일은 수정하거나 삭제하지 마세요.
- JSON을 손으로 다시 입력하지 말고 기존 데이터에서 정확하게 추출하세요.
- 한자 수, 독해 수, 문자열, 줄바꿈과 이미지 주소가 손실되지 않아야 합니다.
- 디자인이나 학습 기능을 변경하지 마세요.
- 이번 단계에서는 Google Sheets 동기화 프로그램을 만들지 마세요.

## 목표 구조

```text
public/
└─ data/
   ├─ kanji.json
   └─ stories.json
```

## 작업 내용

1. `index.html`의 한자 JSON을 추출하여 `public/data/kanji.json`으로 저장하세요.
2. 독해 JSON을 추출하여 `public/data/stories.json`으로 저장하세요.
3. 두 파일이 유효한 UTF-8 JSON인지 확인하세요.
4. JSON 추출이 성공한 뒤에만 HTML의 기존 내장 데이터 블록을 제거하세요.
5. `src/main.js`에서 다음 파일을 비동기로 불러오도록 변경하세요.
   - `/data/kanji.json`
   - `/data/stories.json`
6. 데이터가 준비된 뒤 필터 생성, 독해 렌더링, 카드 렌더링이 실행되도록 초기화 순서를 정리하세요.
7. 데이터 로딩 실패 시 빈 화면만 보이지 않도록 사용자에게 이해하기 쉬운 오류 문구와 재시도 방법을 표시하세요.
8. 이번 단계부터 사이트 방문 시 Google Sheets를 직접 기다리지 않게 하세요.
9. 기존 Google Sheets 관련 코드는 바로 삭제하지 말고, 사용되지 않는 상태로 분리하거나 주석 없이 별도 함수로 보존하세요. 다음 동기화 단계에서 재사용할 수 있도록 하세요.
10. JSON 데이터는 사이트의 기본 데이터 원본으로 사용하세요.

## 데이터 검증

다음을 프로그램으로 확인하세요.

- 한자 데이터가 정확히 2,324개인지
- 독해 데이터가 정확히 19개인지
- 각 한자에 `한자` 값이 있는지
- 중복 한자가 있는지
- JSON 구문 오류가 없는지
- 기존 데이터에 있던 이미지·획순·읽기·예시 단어 필드가 유지되는지

실제 데이터 수가 위 숫자와 다르다면 임의로 맞추지 말고, 기존 HTML 데이터의 실제 개수와 차이를 보고하세요.
