# 작업: 한자 이미지 이전을 위한 현황 조사

이번 작업에서는 이미지를 다운로드하거나 URL을 수정하지 말고, 현재 이미지 자료의 규모와 상태만 분석하세요.

## 보호 조건

- 이미지 다운로드 금지
- JSON의 이미지 주소 변경 금지
- Google Drive 파일 수정 금지
- 백업 파일 수정 금지
- 새로운 저장소 서비스 연결 금지

## 조사할 내용

`public/data/kanji.json`을 분석하여 다음 내용을 정리하세요.

1. 이미지 관련 필드 이름
2. 이미지 종류별 URL 개수
3. Google Drive URL 개수
4. 그 밖의 호스트별 URL 개수
5. 빈 이미지 주소 개수
6. 중복 이미지 주소 개수
7. HTTP와 HTTPS 주소 개수
8. URL 형식이 잘못된 것으로 보이는 항목
9. 획순 이미지가 있는 한자 수
10. 한자당 이미지 개수 분포

## 결과물

프로젝트 안에 다음 보고서를 만드세요.

```text
reports/image-inventory.md
```

가능하면 사람이 확인할 수 있는 CSV도 만드세요.

```text
reports/image-inventory.csv
```

CSV에는 최소한 다음 항목을 넣으세요.

- 한자
- 이미지 종류
- 원본 URL
- 호스트
- 중복 여부
- 형식 검사 결과

## 제안

조사 결과를 기준으로 다음 방식의 장단점을 비교하세요.

- `public/images`에 직접 저장
- Supabase Storage
- Cloudflare R2

전체 이미지 수와 예상 관리 난이도를 고려해 가장 적절한 방식을 제안하되, 실제 이전은 수행하지 마세요.

## 검증과 보고

- 분석한 한자 수
- 발견한 전체 이미지 주소 수
- 누락·중복·오류 의심 개수
- 추천 저장 방식
- 다음 단계에서 필요한 작업
