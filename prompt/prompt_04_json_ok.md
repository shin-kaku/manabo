# 작업: Google Sheets 데이터를 로컬 JSON으로 안전하게 동기화

현재 웹사이트는 다음 로컬 파일을 읽어 작동합니다.

- `public/data/kanji.json`
- `public/data/stories.json`

이번 작업에서는 사이트 방문자가 Google Sheets를 직접 호출하지 않도록 유지하면서, 운영자가 VS Code에서 명령 한 번으로 최신 시트 내용을 JSON으로 갱신할 수 있게 하세요.

## 목표

다음 명령으로 데이터를 갱신할 수 있어야 합니다.

```bash
npm run sync-data
```

## 목표 구조

```text
scripts/
└─ sync-sheets.mjs

.env.example
.env.local
```

## 보호 조건

- 이름에 `backup`이 들어간 파일을 수정하지 마세요.
- 동기화에 실패했을 때 기존 정상 JSON을 훼손하지 마세요.
- 공개할 필요가 없는 시트 열을 JSON에 포함하지 마세요.
- 관리자 키, 비밀번호 또는 민감한 정보를 브라우저 코드에 넣지 마세요.
- 불필요한 패키지를 설치하지 마세요.
- Apps Script 주소는 비밀번호가 아니지만 환경설정으로 분리하세요.

## 작업 내용

1. `scripts/sync-sheets.mjs`를 만드세요.
2. 기존 Apps Script 배포 주소에서 한자와 독해 데이터를 받아오세요.
3. Apps Script 주소는 `.env.local`의 다음 변수에서 읽으세요.

```env
MANABO_SHEETS_API_URL=
```

4. 주소 예시만 들어 있는 `.env.example`을 만드세요.
5. `.env.local`이 Git에 포함되지 않도록 `.gitignore`를 확인하세요.
6. `package.json`에 다음 명령을 추가하세요.

```json
"sync-data": "node scripts/sync-sheets.mjs"
```

Node 버전과 환경변수 읽기 방식이 맞지 않으면 현재 프로젝트에 설치된 Vite 기능을 활용하되, 새로운 환경변수 패키지는 가급적 설치하지 마세요.

## 공개 필드 제한

시트가 반환하는 모든 열을 그대로 저장하지 마세요. 현재 사이트 코드가 실제로 사용하는 필드를 조사하고 공개 필드 허용 목록을 만드세요.

최소한 다음 유형을 검토하세요.

- 한자
- 훈음
- 풀이
- 획수
- 학년
- JLPT
- 정렬 관련 값
- 이미지 주소
- 획순 이미지
- 읽기
- 예시 단어
- 관련 한자

실제 헤더 이름은 기존 데이터와 사이트 코드를 기준으로 사용하세요. 이름을 임의로 바꾸지 마세요.

내부 메모, 수정 기록, 작업자 정보 등 사이트에서 사용하지 않는 열은 제외하세요.

## 안전한 저장 방식

1. 받은 응답이 정상인지 먼저 검사하세요.
2. 필수 필드와 배열 개수를 검사하세요.
3. 임시 파일에 JSON을 저장하세요.
4. 임시 파일의 JSON을 다시 읽어 유효성을 확인하세요.
5. 모든 검사가 성공한 경우에만 기존 JSON을 교체하세요.
6. 실패하면 기존 파일을 그대로 유지하고 원인을 출력하세요.
7. 동기화된 날짜와 데이터 개수를 터미널에 표시하세요.

## 검증

- `npm run sync-data` 성공
- 한자와 독해 개수 출력
- JSON 구문 검사
- `npm run build` 성공
- 동기화 후 주요 기능 정상 작동
- 사이트를 새로 열 때 Apps Script를 직접 호출하지 않는지 확인
