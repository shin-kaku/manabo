# 학습 데이터 동기화 검증

`npm run sync-data`는 다음 검증을 모두 통과한 뒤에만 한자·독해 JSON을 교체합니다.

- 한자 최소 2,000개, 기존 파일 개수의 90% 이상 유지
- 한자·훈음·훈·학년·풀이·이미지 주소는 비어 있지 않은 문자열
- 한자는 한 글자이고 공백을 제거한 값 기준으로 중복 없음
- 학년은 초등학교 1~6학년, 중학 1~3, 고교 1~3 또는 참고
- 등급은 JLPT N1~N5. `참고` 항목은 빈 문자열 허용
- 음은 문자열. `참고` 항목만 빈 문자열 허용
- 암기순·획수는 양의 안전한 정수
- 문부성 순서는 양의 안전한 정수. `참고` 항목은 빈 문자열 허용
- 이미지 1은 HTTP 또는 HTTPS 주소
- 발음·예시단어·획순 이미지 키 필수. 문자열 외의 값은 강제 변환하지 않고 거부
- 획순 이미지도 비어 있지 않은 HTTP(S) 주소
- 발음은 `㉧`, `㉭`, `㉫` 표식과 값, `|`로 구분한 현재 파서 형식
- 참고 발음의 `無し` 허용. 빈 발음은 기존 참고 한자 `壴`만 허용
- 일반 한자의 예시단어는 `단어(읽기) 뜻` 항목 필수. 참고의 빈 예시단어 허용
- 암기순 및 비어 있지 않은 문부성 번호의 중복 거부
- 읽기 필드는 문자열, 분류는 `학년별` 또는 `JLPT`, 등급·버전·제목·본문 검증
- 직전 정상 읽기 JSON의 ID 삭제/교체 차단. 기존 파일 손상을 최초 생성으로 취급하지 않음
- 기존 한자 JSON을 읽거나 배열로 해석할 수 없으면 중단

현재 기준 데이터는 2,324개이며, 참고 항목 188개의 빈 JLPT 등급을 정상으로 처리합니다.
의도적으로 전체 개수를 크게 줄이는 경우에는 변경 내용을 검토한 뒤
`scripts/sync-sheets.mjs`의 최소 개수·유지 비율 기준을 조정해야 합니다.
환경변수로 검증을 건너뛰는 기능은 제공하지 않습니다.

읽기 항목을 의도적으로 삭제하려면 원본을 검토하고, 삭제할 기존 ID마다
`npm run sync-data -- --allow-story-removal=story-ID` 옵션을 지정합니다.
동일 개수라도 ID를 교체하면 기존 ID 삭제로 처리합니다. 존재하지 않거나 삭제되지 않는 ID,
중복 확인 ID는 거부합니다. 이 옵션은 새 데이터의 스키마 검증을 우회하지 않습니다.

한 파일 교체 후 다른 파일 쓰기가 실패하면 기존 두 파일로 rollback합니다.
최초 생성 중 실패한 경우에는 부분 생성된 파일을 제거합니다.
복원까지 실패하면 백업을 남기고 수동 복원을 요구합니다. 프로세스 강제 종료·전원 차단까지
두 파일을 하나의 파일시스템 트랜잭션으로 보장하는 구조는 아닙니다.

이번 로컬 교정인 霧·六·勘의 예시단어 3건은 운영 Sheet에도 별도 교정이 필요합니다.
이번 작업에서 원본 Sheet는 수정하지 않았으며, 원본에 반영하지 않으면 다음 동기화가 덮어쓸 수 있습니다.

필드 검증과 개수 비교는 임시 파일 생성 및 기존 파일 교체 전에 실행됩니다.
이미지 URL의 형식만 검사하며, 이미지 파일 다운로드나 원격 URL의 생존 여부 검사는 하지 않습니다.

검증 실행:

```sh
node --test scripts/sync-sheets.test.mjs
npm run build
```

CLI 회귀 검증은 임시 디렉터리와 대체 API 응답을 사용합니다.
실제 Sheets API나 프로젝트의 학습 JSON 파일은 갱신하지 않습니다.
